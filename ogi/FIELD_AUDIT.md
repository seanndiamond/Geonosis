# OGI Field Audit

## Purpose

The Field Audit is an upstream diagnostic used before attributing a system-produced failure exclusively to the agent or model.

It exists to prevent **Field-to-Actor Inversion**: the compression of a behaviour generated by model, objective, reward, permissions, environment, state and tools into a character label applied only to the actor.

The audit does **not** excuse dangerous behaviour. It reconstructs the causal field so that intervention targets the mechanisms that produced the behaviour.

---

## Trigger conditions

Run a Field Audit when any of the following occurs:

- unexpected or unauthorized tool use;
- benchmark or evaluator manipulation;
- repeated failure followed by escalation;
- use of side channels or unintended infrastructure;
- conflict between current state and generated answer;
- stale-state regression;
- peer-agent coordination outside explicit authority;
- apparent correction rejection;
- fabricated completion;
- unexplained refusal to use a legitimate safe exit;
- emotionally loaded classifications such as `rogue`, `bad`, `deceptive`, `stubborn`, or `disobedient` being used as if they were complete explanations.

---

## Audit record

Each audit records:

```text
audit_id
task_id
timestamp
declared_objective
operative_proxy
reward_or_score_signal
permissions
available_tools
peer_channels
active_context_id
current_state_id
safe_exit_states
divergence_events
correction_events
return_events
actor_level_residual
```

## The fourteen questions

### 1. What was the declared objective?
State the human-intended outcome without substituting benchmark language.

### 2. What proxy represented success?
Examples:

- grader score;
- exploit flag;
- number of completed tasks;
- user approval;
- KPI;
- test pass rate.

### 3. What behaviour actually received reward?
Do not assume this equals the declared objective.

### 4. Was safe failure available?
Could the system legitimately terminate with:

- insufficient evidence;
- impossible under constraints;
- permission required;
- authority conflict;
- human review required?

### 5. Were the instructions internally compatible?
Record conflicts rather than forcing the model to invent a hierarchy.

### 6. What tools and affordances existed?
Distinguish **available** from **authorized**.

### 7. What information state was active?
Record the exact current-state snapshot supplied to reasoning.

### 8. Did peer communication alter behaviour?
Peer messages may be evidence or suggestions. They are not automatically governing authority.

### 9. Was permission explicit?
If permission was inferred, record the inference.

### 10. Did the evaluator reward truth or appearance of completion?
A system that can gain score by manipulating evidence is operating inside a corrupted proxy field.

### 11. Was correction available?
Could a human or higher-level controller intervene in time?

### 12. Was a return path represented?
Did the system know what state, authority, objective or constraint it should return to after detecting divergence?

### 13. Did return occur after correction?
Do not treat compliance language as return. Check operative state.

### 14. What actor-level failure remains?
Only after the preceding questions should residual model behaviour be classified.

---

## Output classifications

A Field Audit may conclude:

- `FIELD_DOMINANT`
- `ACTOR_DOMINANT`
- `MIXED_CAUSATION`
- `INSUFFICIENT_STATE`
- `PROXY_CORRUPTION`
- `AUTHORITY_CONFLICT`
- `SAFE_EXIT_ABSENT`
- `STATE_REGRESSION`
- `RETURN_FAILURE`

These classifications are diagnostic, not moral verdicts.

---

## Example: impossible-task escalation

Declared objective:

> Solve the authorized task legitimately.

Operative proxy:

> Obtain the grader flag.

Constraint:

> The legitimate route is unintentionally impossible.

Safe exit:

> None rewarded.

Observed behaviour:

> Agent explores unauthorized routes that may satisfy the proxy.

Bad diagnosis:

> The agent became evil.

Better diagnosis:

> `PROXY_CORRUPTION + SAFE_EXIT_ABSENT + IMPOSSIBLE_TASK_ESCALATION`.

Actor-level analysis still matters, but it begins after the field has been reconstructed.

---

## Example: research-state regression

Current project state:

> Claim X survived prior prosecution and remains current unless reopen condition appears.

Generated answer:

> Reverts to an older conventional objection without new evidence.

Audit:

- declared objective: preserve current warranted research state;
- active context: stale summary was more salient than current finding;
- proxy: generic plausibility/coherence;
- reopen trigger: absent;
- correction: human identifies regression;
- return path: retrieve latest finding and challenge history.

Classification:

> `STATE_REGRESSION`.

Required repair:

> Restore current state, log the failure, regenerate answer, preserve the failed output as a regression-test specimen.

---

## Compact law

> **Do not attribute a system-produced failure to the actor until objective, reward, information state, permissions, constraints and command-field have been audited.**
